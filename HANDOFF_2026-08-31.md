**Fix 1 — the gate that silently skipped every row.**

Node `Has research_facts?` passes a row only if the cell contains the literal
word `"facts"`. A run of 118 rows sent all 118 down the FALSE branch, so nothing
downstream ever executed. It looked like the workflow was stuck; it had
actually finished, having rejected everything.

Change the condition to:

```
leftValue:  ={{ String($json.research_facts || '').trim().length }}
operator:   number / gt
rightValue: 50
```

**Fix 2 — add the `Quality Guard` node.**

A new Code node sits between `Code JSON Parser` and `Update Row in Sheet`, so
nothing reaches the sheet or Supabase unchecked. Take its exact `jsCode` from
the `Quality Guard` node in `n8n-idea-pipeline-v2.json`.

Wiring: `Code JSON Parser` -> `Quality Guard` -> `Update Row in Sheet`.

It rejects the unambiguous and only flags the arguable. That distinction is not
stylistic — it came from checking the 290 live rows. A crude banned-word scan
raised 11 problems and only 5 were real. These four were correct English that a
naive guard would have destroyed:

- "you unlock the lower steel cabinet" — a key in a lock, not marketing
- "a seamless loop" — the standard audio term
- "seamless reweaving" — literally no visible seam
- "post-1960 premium pens" — a product category, not a date

So `unlock`, `seamless`, `leverage`, `empower` etc. go into a `quality_flags`
field for review and never fail a row. Only filler with no legitimate use is
fatal. A recent year (within 2 of the current year) is fatal because it dates
the page; an older year is only flagged. Naming an AI vendor is always fatal.

### A decision that was made and NOT yet implemented

The blog branch currently posts to **WordPress**. That is wrong.
`PROJECT_BRIEF.md` §10 says explicitly: *"Blog lives on our own Next.js/Supabase
stack, not WordPress. Headless WordPress caused hosting issues previously and is
not worth revisiting."*

Worse, `/blog` on the live site fetches `https://nutrizoe.in` — recorded in
`IDEAVAULT-MASTER-DEV-GUIDE.md` as *"placeholder only, will be replaced"*. So the
blog section currently points at an unrelated site.

The agreed plan, not yet built:

1. New `blog_posts` table in the EXISTING Supabase project (additive, never
   touches `ideas`).
2. `/blog` and `/blog/$slug` read that table instead of WordPress.
3. The n8n blog branch writes there; the WordPress credential is dropped entirely.
4. **Blog cover images go in the repo under `/public/blog/`**, served by Vercel's
   CDN — not Supabase Storage. Reason: Supabase free gives 5 GB egress/month,
   which is roughly 25,000 image loads; Vercel's free tier is ~20x that and the
   images are already in the deploy. 200 posts of text is ~2 MB against a 500 MB
   cap, so storage was never the constraint — bandwidth was.
5. One Supabase account only. A second account was considered and rejected: two
   Postgres databases cannot join, free projects pause after ~7 days idle, and it
   solves storage (200x headroom) while not solving egress.
